# 十倍股评分逻辑评审总结与改造清单（A股早期识别）

> 基于现有《十倍股评分逻辑详解》梳理的结论与行动项  
> 目标：把系统从“宽松打分/高推荐率”升级为“低通过率 + 可解释 + 可校准”的早期十倍股识别框架

---

## 1. 结论：为什么会出现“评分卡大量 100 分、推荐率极高”

现有 ScoreCard 与 TenbaggerEvaluator 的共同特征是：

- **大量维度采用“基础分 + 加分项 + 上限 100”** 的结构；
- **缺失数据没有显式惩罚**（或默认值偏高）；
- 多个维度目前是 **TODO/占位默认值**（如产业位置固定 60、研报数量固定 5），导致分数分布被“压扁/抬高”；
- Stage 相关分数在两个层级中重复出现（ScoreCard 的兑现路径 + Tenbagger 的 stage），且 **S2/S3 天生高分**，造成阶段集中时整体分数整体上移。

**关键问题不是“算错了某个指标”，而是：评分体系设计上缺少“杀死候选”的机制（hard filter / veto / 置信度惩罚）。**

---

## 2. 现行打分链路的结构性缺陷（按优先级）

### P0：缺失/占位不会扣分 → 评分虚高
- 产业位置：固定 60（TODO）
- 研究关注：report_count 固定 5（TODO）
- altdata/industry 等维度在 Tenbagger 侧若缺数据，通常仍可拿到基础分 50
- 结果：**数据越少越不吃亏，甚至更容易高分**（这是最危险的模式）

### P0：阈值加分型规则 → 大量股票挤在 80~100
例如财务拐点、成长性、动量等均为：
- base=50
- 满足条件 +15/+20/+25
- clamp 到 100
这会导致：
- 龙头/大票更容易“过阈值”，但未必是“十倍早期”
- 评分分布缺乏区分度（方差低、top 聚集）

### P0：Stage 双重计入导致总分系统性抬升
- ScoreCard：兑现路径 20%
- Tenbagger：stage 20%
若 StageMachine 默认或偏好输出 S2/S3，则 **两次加成** 直接抬高总分。

### P1：权重结构导致 ScoreCard 失真会放大到总评
- Tenbagger 中 scorecard 权重最高（25%），scorecard 一旦虚高会直接拉高推荐。

## 3. “更有效的A股十倍股早期识别系统”应有的核心原则

### 原则 A：先做“必要条件/否决项”，再做“加分排序”
十倍股早期识别不是平均主义打分，而是：
- **缺关键条件 = 不可能**
- **存在致命风险 = 直接淘汰**
然后才在剩余样本里做排序。

### 原则 B：缺失必须惩罚 + 输出置信度（confidence）
建议每次评估输出：
- missing_ratio（缺失比例）
- data_freshness（数据新鲜度）
- confidence = f(missing_ratio, freshness, coverage)
并将分数做：
- score_final = score_raw * confidence
或：confidence < 阈值则直接降级/不推荐。

### 原则 C：用“截面分位/同行对比”替代“阈值加分”
阈值型规则只适合做 hard filter，不适合作为主评分来源。主评分应尽量采用：
- 同行业/同市值段分位数
- 斜率/变化率（拐点）而非绝对水平
- winsorize + z-score + clamp

### 原则 D：Stage 只作为“输出解释”，不要重复作为输入增益
阶段可用于描述“处于哪段路径”，但不应在两个层级重复计分。

## 4. 立刻可落地的改造清单（不破坏现有接口）

### P0（当天可做）：把“评分虚高”压下来
1) **加入数据质量门控**
- 若 financial/events/altdata 覆盖不足：ScoreCard/tenbagger 直接降级或不推荐
- 输出字段：missing_ratio、confidence、quality_flag

2) **对占位维度设置“保守分 + 惩罚”**
- 产业位置 TODO：从固定 60 改为固定 30~40，并标记 `placeholder=True`
- 研报数 TODO：缺数据按“共识未知”处理，给 50 或更低（不要默认高分）

3) **取消 Stage 双重计分**
- 方案：TenbaggerEvaluator 的 stage 维度保留；ScoreCard 的兑现路径先降权或不计入总分（或反之）
- 目标：避免阶段集中时总分整体抬升

4) **引入“一票否决”规则引擎（最少 5 条）**
建议首批规则（可全用公开财务+公告代理实现）：
- ST/退市风险/重大违规
- 股权质押比例极高 + 股价接近平仓风险（可用代理阈值）
- 经营现金流长期为负且营收增长来自应收/存货堆积
- 高杠杆短债压力（短债/货币资金、资产负债率）
- 商誉/非经常损益主导利润（质量差）

### P1（1~2 周）：让分布“可区分、可校准”
5) **把财务拐点、成长性、估值错配改为“分位制”**
- 同行业分位：ROIC/毛利率变化、营收增速、利润增速、现金流质量
- 输出：raw, peer_percentile, sub_score

6) **给每个维度输出可解释证据**
- 例如财务拐点：毛利率同比/环比、营收增速斜率、OCF/净利比
- 动量：均线结构、成交额斜率、相对强度分位

7) **推荐率目标管理**
- 系统应该天然低通过率：建议在初版把 A 以上控制在 10%~30%
- 用阈值与规则引擎共同实现，而不是靠总分硬切。

### P2（1~2 月）：从“打分”升级为“十倍路径模型”
8) **建立十倍标签与回测指标**
- 标签：入选日起 3/5 年内最大涨幅 ≥ 3x/5x/10x（复权），并记录起涨前最大回撤
- 指标：HitRate@K、Time-to-Inflection、MaxDD-before-takeoff、分行业/市值分层表现

9) **建立三轴阶段机（基本面/资金/预期）**
- StageMachine 不再是单点状态，而是三轴触发组合，避免“默认 S2”。

## 5. 针对当前代码/配置的直接建议（对应文档）

- ScoreCard：
  - 产业位置（20%）当前是固定 60：会把总分“抬底”，且没有区分度；应改为保守分 + placeholder 惩罚，或降权直至有真实 industry_graph。
  - 兑现路径（20%）与 Tenbagger 的 stage（20%）重复；至少先去掉一个。
  - 财务拐点、组织信号、估值错配均为“基础分+加分+clamp 100”，应逐步替换为分位/斜率模型。
  - 研究关注（10%）report_count 固定 5 会导致大量股票落在同一档；缺数据不应被当成“研报少=早期高分”。

- TenbaggerEvaluator：
  - scorecard 权重最高（25%）：在 scorecard 未修复前，会放大虚高分与高推荐率。
  - growth/momentum/altdata 等维度同样是 base=50 + 加分，上限 100；需要改成分位或引入置信度衰减。
  - risk 维度仅 5% 且规则很少：对 A 股“踩雷风险”抑制不足，应优先补强 veto。

## 6. 交付物建议（让系统可复现、可追溯）

每次运行输出一个 Run Bundle（JSON + 报告）：
- run_id、git_commit、配置快照、数据版本时间戳
- 每只股票：各维度 raw/percentile/score、触发的规则、否决原因、confidence
- 汇总：分数分布统计（min/median/max/std，100 分占比报警）

## 7. 下一步最小闭环（建议顺序）

1) scorecard/tenbagger 增加缺失惩罚 + confidence 输出  
2) 去掉 Stage 双重计分  
3) 加 5 条 veto（淘汰雷）  
4) 把财务拐点/成长性改为同行分位（先做 2~3 个关键指标即可）  
5) 用历史回测校准推荐率与阈值（HitRate@K 为主）
