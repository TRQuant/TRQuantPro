## 📊 当前知识库架构

### 数据结构

```python
{
    "items": [
        {
            "id": "kb_xxx",
            "title": "标题",
            "content": "内容",
            "tags": ["标签1", "标签2"],
            "type": "reference",
            "source": "URL",
            "created_at": "2026-01-01",
            "useful_count": 0,
            "_score": 10  # 搜索评分
        }
    ]
}
```

### 搜索算法

**当前实现** (`knowledge_search`):
1. 加载JSON文件
2. 字符串匹配（title、content、tags）
3. 简单评分系统（title=10, content=5, tags=3）
4. 增强搜索（代码块、API函数、因子名提取）
5. 按分数排序

**特点**:
- ✅ 简单快速
- ✅ 精确匹配效果好
- ❌ 不支持语义相似度搜索
- ❌ 不支持同义词匹配
- ❌ 不支持向量检索

## ❌ 当前限制

### 1. 关键词匹配的限制

**问题**:
- 需要精确的关键词匹配
- 不支持同义词（如"因子"和"factor"）
- 不支持语义相似度（如"价格数据"和"行情数据"）
- 不支持上下文理解

**示例**:
- 搜索"get_price"能找到相关内容 ✅
- 搜索"获取价格"可能找不到相关英文内容 ❌
- 搜索"行情数据"可能找不到"价格数据"相关内容 ❌

### 2. 评分系统的限制

**问题**:
- 基于关键词出现次数
- 无法理解语义相关性
- 无法处理概念相似但用词不同的情况

## 🚀 RAG技术实施建议

### 方案1: 向量检索（推荐）

**技术栈**:
- Embedding模型：sentence-transformers（中文模型）
- 向量数据库：FAISS（本地）或Chroma（轻量级）
- 检索方式：向量相似度搜索

**实施步骤**:
1. 为每个知识条目生成向量嵌入
2. 存储向量到向量数据库
3. 查询时转换为向量并搜索
4. 结合关键词匹配和向量检索（混合检索）

### 方案2: 混合检索（最佳）

**技术栈**:
- 向量检索（语义搜索）
- BM25关键词检索（精确匹配）
- Reranker（结果重排）

**实施步骤**:
1. 并行执行向量检索和BM25检索
2. 合并结果并去重
3. 使用Reranker模型重排
4. 返回Top-K结果

### 方案3: 使用现有RAG框架

**可选框架**:
- LangChain（集成向量数据库和检索器）
- LlamaIndex（专门的RAG框架）
- Haystack（端到端RAG框架）
