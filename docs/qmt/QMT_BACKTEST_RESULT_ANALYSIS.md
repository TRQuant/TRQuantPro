## 🔧 已修复的问题

### 1. 缓存键包含barpos（关键修复）

**问题**：
- 历史数据缓存键不包含barpos
- 导致所有调仓使用相同的历史数据
- QMT的`get_history_data`是相对于当前bar的，不同bar需要不同的缓存

**修复**：
```python
# 修复前
cache_key = f"{field}_{days}"  # 历史数据不包含barpos

# 修复后
cache_key = f"{field}_{days}_bar{barpos}"  # 包含barpos
```

**效果**：
- 每个bar使用正确的历史数据
- 每次调仓会选出不同的股票（基于最新的因子计算）
- 轮动逻辑正常工作

### 2. 添加回报率计算

**新增功能**：

- 计算总资产（现金 + 持仓市值）
- 计算总回报和回报率

## 🎯 优化建议

### 1. 因子筛选优化（优先级：高）

**当前问题**：
- 只有18只股票通过筛选（5404只中）
- 通过率：18/5404 = 0.33%
- 过于严格，导致选股范围太小

**优化方案**：
- **调整因子权重**：降低严格因子的权重
- **放宽过滤阈值**：
  - `MIN_MOMENTUM_20D`: 0.0% → -2.0%（允许轻微负动量）
  - `MIN_MARKET_CAP`: 30.0 → 20.0（扩大市值范围）
  - `MAX_MARKET_CAP`: 200.0 → 300.0（包含更多大盘股）
- **动态阈值**：根据市场环境调整（牛市/熊市）

### 2. 选股多样性优化（优先级：中）

**当前问题**：
- 每次调仓可能选出相同或相似的股票
- 缺乏行业/主题分散

**优化方案**：
- **行业分散**：限制同一行业的最大持仓数量
- **相关性过滤**：避免选择高度相关的股票
- **市值分散**：确保大中小盘股的合理配置

### 3. 轮动逻辑优化（优先级：中）

**当前问题**：
- 轮动可能过于频繁（每周调仓）
- 没有考虑交易成本

**优化方案**：
- **调仓阈值**：只有当新股票分数显著高于持仓股票时才调仓
- **交易成本考虑**：计算调仓的净收益（收益 - 交易成本）
- **持仓周期**：考虑最小持仓周期（如至少持有2周）

### 4. 风控优化（优先级：高）

**当前问题**：
- 止损止盈逻辑简单（仅20MA）
- 没有仓位管理

**优化方案**：
- **动态止损**：根据ATR设置止损距离
- **分批止盈**：达到目标收益后分批卖出
- **仓位管理**：根据市场环境调整仓位（牛市满仓，熊市减仓）

## 📝 技术细节

### 缓存修复说明

**QMT的`get_history_data`行为**：
- `get_history_data(22, '1d', 'close', 0)` 返回从**当前bar往前推22天**的数据
- 不同bar返回的数据不同（时间窗口不同）
- 因此，缓存键必须包含barpos

**修复后的缓存策略**：
- **历史数据（days>1）**：`{field}_{days}_bar{barpos}`（包含barpos）
- **当日数据（days=1）**：`{field}_{days}_{date}`（包含日期）

### 回报率计算

```python
# 计算持仓市值
position_value = sum(current_price * lots * 100 for stock, lots in holdings)

# 计算总资产
total_assets = cash + position_value

# 计算回报率
return_rate = (total_assets - initial_capital) / initial_capital * 100
```
