## 行情相关问题

### 1. 全推接口和订阅接口的分笔行情没有5档行情

**问题描述**：
`get_full_tick`, `subscribe_while_quote`函数中获取分笔行情没有5档行情，只有最新价。

**解决办法**：
修改行情源对应的全推行情级别：
1. 打开QMT客户端
2. 点击右下角【行情】按钮
3. 选择【智能下载】或【行情设置】
4. 在行情级别设置中，将全推行情级别调整为包含5档行情的级别
5. 保存设置并重启客户端

**注意**：全推行情级别设置会影响`get_full_tick`和`subscribe_whole_quote`函数获取的数据内容。

---

### 2. 行情中心和交易中心的区别

**行情中心**：
- 控制单支订阅
- 影响函数：`subscribe_quote`（单支订阅）
- 用于获取单个股票的实时行情数据

**交易中心**：
- 影响全推数据
- 影响函数：`get_full_tick`（全推行情）、`subscribe_whole_quote`（全推订阅）
- 用于获取所有股票的实时行情数据

**使用建议**：
- 如果只需要获取单个股票的行情，使用行情中心（`subscribe_quote`）
- 如果需要获取多个股票的行情，使用交易中心（`get_full_tick`或`subscribe_whole_quote`）

### 3. passorder使用对手价下单报错

**问题描述**：
`passorder`参数`prType`填写`14`(对手价下单)时，委托价格有误，或信息提示对手价无效，无法下单！

**解决办法**：
修改行情源对应的全推行情级别（同问题1）：
1. 打开QMT客户端
2. 点击右下角【行情】按钮
3. 选择【智能下载】或【行情设置】
4. 在行情级别设置中，将全推行情级别调整为包含5档行情的级别
5. 保存设置并重启客户端

**原因分析**：
- 对手价下单需要获取买一价或卖一价
- 如果全推行情级别不够，无法获取5档行情数据
- 导致无法获取对手价，下单失败

**代码示例**：
```python
# 确保全推行情级别包含5档行情后，才能使用对手价下单
passorder(23, 1101, account, stock, 14, -1, volume, '备注', 2, ContextInfo)
# 参数14表示对手价，-1表示使用对手价（买一或卖一）
```

### 4. handlebar中获取期货tick频率问题

**问题描述**：
在`handlebar`中获取期货tick时，tick是3S一个而非0.5s一个。

**原因分析**：
`handlebar`函数是逐K线驱动的，在实时行情中，`handlebar`会随着主图标的tick的更新被调用。
在这个问题场景中，主图的标的通常被设置为股票，而股票的tick通常是3s一个，这就导致`handlebar`函数3s才被调用一次。

**解决方法**：

**方法1：使用定时器(run_time)进行计算**
```python
def init(ContextInfo):
    ContextInfo.run_time("myCallback", "500mSecond", "2024-01-01 09:00:00")

def myCallback(ContextInfo):
    # 每0.5秒执行一次
    tick = ContextInfo.get_full_tick(['IF2312.CFFEX'])
    # 处理tick数据
```

**方法2：使用订阅推送(subscribe)，在回调函数中进行计算**
```python
def init(ContextInfo):
    subscribe_quote('IF2312.CFFEX', 'on_tick', ContextInfo)

def on_tick(ContextInfo, tick_data):
    # tick数据回调，实时处理
    pass
```

**方法3：将主图设置为期货品种**
如果需要在`handlebar`中进行期货策略编写，建议将主图设置为期货品种，来保证`handlebar`调用频率。

**注意**：期货tick通常是0.5秒一个，但如果主图是股票，`handlebar`调用频率会受股票tick频率（3秒）影响。

### 5. 非交易时间段handlebar被调用

**问题描述**：
在非交易时间段`handlebar`也会被调用。

**原因分析**：
`handlebar`受行情数据推送驱动，在非交易时段，行情服务会做一系列准备工作，其中可能伴随着服务重启，在重启后为了保证数据齐全，客户端会重新订阅数据，这时服务会推送最新的数据，客户端会把推送的最新数据更新至缓存，并向上层策略推送更新，也就是触发`handlebar`执行。

这个合并数据的驱动执行只会在最新一根bar而不会在历史范围。

**解决方法**：
在`handlebar`中判断交易时间，非交易时间直接return：
```python
import time

def handlebar(ContextInfo):
    # 获取当前时间
    now = time.strftime('%H%M%S')
    
    # 判断是否在交易时间
    # 上午：09:30-11:30
    # 下午：13:00-15:00
    if now < '093000' or (now > '113000' and now < '130000') or now > '150000':
        return  # 非交易时间，直接返回
    
    # 或者使用更精确的判断
    if not ContextInfo.is_last_bar():
        return  # 历史K线，直接返回
    
    # 交易时间内的策略逻辑
    # ...
```

**交易时间段**：
- 上午：09:30-11:30
- 下午：13:00-15:00
- 集合竞价：09:15-09:25（可选）

### 6. 证券状态openint值详细说明

**沪市**：
| 时间段 | 状态 | 编码 |
|--------|------|------|
| 9:15 - 9:25 | 盘前集合竞价 | 12 |
| 9:25 - 14:57 | 盘中连续竞价 | 13 |
| 14:57 - 15:00 | 盘后集合竞价 | 18 |
| 15:00 | 收盘状态 | 15 |
| 15:05 - 15:30 | 盘后定价 | 22 |
| 15:30 | 盘后定价结束 | 23 |
| 上一状态后 | 收盘状态 | 15 |

**深市**：
| 时间段 | 状态 | 编码 |
|--------|------|------|
| 9:15 - 9:25 | 盘前集合竞价 | 12 |
| 9:25 - 9:30 | 休市 | 14 |
| 9:30 - 11:30 | 盘中连续竞价 | 13 |
| 11:30 - 13:00 | 休市 | 14 |
| 13:00 - 14:57 | 盘中连续竞价 | 13 |
| 14:57 - 15:00 | 盘后集合竞价 | 18 |
| 15:00 | 收盘状态 | 15 |
| 15:05 - 15:30 | 盘后定价 | 22 |
| 15:30 | 盘后定价结束 | 23 |
| 上一状态后 | 收盘状态 | 15 |

**使用示例**：
```python
def handlebar(ContextInfo):
    # 获取证券状态
    status = ContextInfo.get_market_status()
    openint = status.get('openint', 0)
    
    # 判断是否在交易时间
    if openint == 13:  # 连续竞价
        # 可以正常交易
        pass
    elif openint == 12:  # 集合竞价
        # 集合竞价期间
        pass
    elif openint == 15:  # 收盘
        # 收盘状态
        return
    elif openint == 14:  # 休市（深市特有）
        # 休市状态
        return
```

## 静态数据问题

### 7. 获取合约乘数和最小变动价位失败

**问题描述**：
报错：`[系统]ERROR：******.**获取合约乘数和最小变动价位失败，跳过`

**解决办法**：
1. 点击QMT客户端右下角【行情】按钮
2. 选择【智能下载】
3. 在数据选项下拉框中勾选【过期合约列表】
4. 点击该面板右下角【开始】
5. 待过期合约数据补充完毕后，即可正常获取过期合约数据

**原因分析**：
- 过期合约数据需要单独下载
- 默认情况下，QMT不会自动下载过期合约数据
- 如果策略需要获取过期合约的合约乘数、最小变动价位等静态数据，需要先下载过期合约列表

**适用场景**：
- 获取期货合约的合约乘数
- 获取期货合约的最小变动价位
- 获取过期合约的静态数据

## 软件运行日志

### 8. 日志文件位置和说明

**日志文件位置**：
日志文件通常在安装目录下的 `.\userdata\log` 文件夹中。

**投研版**：`{安装目录}\userdata\log`
- `XtClient_20210922.log` - 客户端常规日志
- `XtClient_datasource_20210922.log` - 行情数据日志
- `XtClient_Formula_20210922.log` - 策略运行日志
- `XtClient_FormulaOutput.log` - 策略输出日志

**QMT版**：`{安装目录}\userdata\log`
- `XtClient_20210922.log` - 客户端常规日志
- `XtClient_Formula_20210922.log` - 策略运行日志
- `XtClient_FormulaOutput.log` - 策略输出日志
- `XtClient_PerformanceFile_20210922.log` - 客户端流程节点日志

**极简模式**：`{安装目录}\userdata_mini\log`
- `XtMiniQuote_20210917.log` - 行情策略模块日志
- `XtMiniQmt_20210917.log` - 客户端常规日志
- `XtMiniQmt_perform_20210917.log` - 客户端流程节点日志

**日志文件命名规则**：
- 日期格式：`YYYYMMDD`（如`20210922`）
- 每天会生成新的日志文件
- 策略输出日志（`FormulaOutput.log`）会持续追加

**查看日志建议**：
1. **策略运行问题**：查看 `XtClient_Formula_20210922.log`
2. **策略输出**：查看 `XtClient_FormulaOutput.log`
3. **行情数据问题**：查看 `XtClient_datasource_20210922.log`（投研版）
4. **客户端问题**：查看 `XtClient_20210922.log`
